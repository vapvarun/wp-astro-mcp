# wp-astro-mcp — Audit & Remediation Checklist

**Date:** 2026-05-30 · **Version audited:** 3.0.0 · **Branch:** `audit-fixes-2026-05`

Audit covered the TypeScript MCP server (~10.7k LOC, 57 actions) and the WordPress bridge plugin (784 LOC PHP), across five dimensions: PHP security, TS architecture, MCP best practices, tests/deps/build, and sync/export reliability.

Repo hygiene is clean (no committed secrets, `dist/` gitignored, real `config/sites.json` untracked). Architecture, naming, and type discipline are good. **The risk is concentrated in correctness — the export/sync data-integrity layer, the WP bridge preview auth, and dependency advisories.**

## 🔴 Tier 1 — Critical data-loss & auth — ✅ DONE

- [x] **C1** Deletion detection treated any fetch error as "deleted". Now: `get()` throws a distinct `NotFoundError` on 404 (not retried, not wrapped); the deletion probe only deletes on a confirmed `NotFoundError`, and logs+skips on any other error. `sync.ts`, `wp-rest-client.ts`
- [x] **C2** Trashed posts never detected. Now: probe inspects `post.status` and treats `status === 'trash'` as deleted (kept `context=edit` so real drafts stay visible). `sync.ts`
- [x] **C3** Orphaned `in_progress` rows on crash → silent partial export. Now: stale `in_progress` reclaimed to `pending` before each batch; mark-complete wrapped in a transaction; `remaining`/job-completion count `pending`+`in_progress` so a job can't report completed with unfinished rows. `export.ts`
- [x] **C4** JSON-mode write could wipe a collection. Now: atomic temp-file + `rename`; parse failure backs up the file to `.corrupt-*` instead of silently overwriting with `[]`. `content-writer.ts`
- [x] **C5** (PHP) Public draft disclosure via `/verify-token`. Now: `user_can(user_id, 'edit_post', post_id)` enforced after signature check; token hardened with a server-side random nonce stored in a single-use 5-min transient; token accepted via header/POST (query still works). `class-rest.php`, `class-preview.php`
- [x] **C6** Force re-sync broken for non-default post types (`type:'unknown'`). Now: `post_type` carried through `getExportedPostMap` into the force-sync entry. `sync.ts`

## 🟠 Tier 2 — High — ✅ DONE

- [x] **H1** axios SSRF/proto-pollution advisories → upgraded to **axios 1.16.1** via `npm audit fix`. (1 moderate transitive advisory remains; needs a `--force` major bump — deferred, see Tier 3.)
- [x] **H2** 429 aborted the whole operation. Now: `RateLimitError` is retryable in `get()` — honors `Retry-After` else backoff+deterministic jitter, throws only after retries exhausted. `wp-rest-client.ts`
- [x] **H3** Pagination silently truncated when `x-wp-total` absent. Now: all 3 loops fall back to "page until a short page", with a 10k-page safety cap. `wp-rest-client.ts`
- [x] **H4** Webhook signature failed open. Now: signature-present-but-no-secret and signature-mismatch are rejected (timing-safe compare); `webhook_secret`/`webhook_url` added to `SiteConfig` (no more unsafe cast). `sync.ts`, `types/index.ts`
- [x] **H5** No SQLite `busy_timeout` → added `pragma('busy_timeout = 5000')`. `database.ts`
- [x] **H6** Blind `ALTER TABLE` migration. Now: versioned `runMigrations()` gated on `PRAGMA user_version`; `ensureSyncSchema()` is a no-op delegating to DB init. `database.ts`, `sync.ts`
- [x] **H7** `export_validate` always reported 0 issues. Now: real `ConversionIssue[]` threaded through `WriteResult` and stored serialized; validate surfaces true counts. `content-writer.ts`, `export.ts`
- [x] **H8** GitHub PAT written to `.git/config`. Now: remote stored token-free; auth via process-scoped `-c http.extraHeader` per push (never at rest). `github.ts`
- [x] **H9** (PHP) Webhook secret rendered as `type="password"`; public `/health` trimmed to `{status, plugin_version}` with verbose fields gated behind `manage_options`. `class-settings.php`, `class-rest.php`
